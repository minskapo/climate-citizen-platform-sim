# 화면 점검표 (Task 22)

점검 방법

- `QA_SHOTS=1 SIM_PASSCODE=… npx playwright test`로 실제 데이터를 만든 뒤 데스크탑 1440 · 모바일 390 스크린샷을 `test-results/qa/`에 저장하고, `docs/figma/*/*.png` 사본과 나란히 비교했다.
- 같은 실행에서 화면마다 개발용 표기 자동 검사를 했다(`e2e/helpers.ts`의 `checkScreen`): 「플랫폼 공통 항목」 · 「캠페인 설정에 따라 자동 구성」 · 「캠페인별 맞춤 영역」 · 「블록형 샌드박스」 · 「위치 ①②③」 문구와 화면 코드(H-2, D-1p, M-1a 등)가 사용자 화면에 없어야 통과. 관리자 화면은 화면 코드만 검사(관리자 편집기의 「캠페인별 맞춤 영역 (블록형 웹 도구)」는 실제 설정 항목 이름이라 허용).
- 시안의 예시 숫자 · 이름(312명, 「새해 1.5도 한달살기」 등)은 빈 상태로 시작하는 체험판이라 다르게 보이는 것이 정상이다. 이 차이는 따로 적지 않았다.
- 결과 표기: **OK**(문구 · 배치가 시안과 맞음) · **고침**(이번에 고침) · **차이**(알고 둔 차이와 이유) · **흐름**(스크린샷 비교 없이 E2E 흐름 · 이전 작업의 시안 대조로 확인).
