## 1. 왜 만드는가

녹색전환연구소(녹전)는 기후시민플랫폼을 전면 개편하고 있다. 기능과 화면은 Figma 시안으로 확정 단계에 있고, 12월 개발 업체 착수 전에 기획을 굳혀야 한다.

시안은 클릭만 되는 그림이라, 실제로 여러 사람이 동시에 쓰면 어떤 느낌인지, 캠페인이 4주 동안 어떻게 흘러가는지, 운영자가 캠페인을 직접 만들어 보면 어디가 막히는지를 알 수 없다.

이 사이트는 **녹전 팀원과 파트너 단체가 플랫폼을 실제로 사용해 보며 감을 익히고, 그 경험으로 기획을 확정하기 위한 체험용 웹사이트**다. **[결정]**

- 의견을 수합하는 창구가 아니다. 의견 게시판·설문 기능은 두지 않는다. **[결정]**
- 성공의 모습: 팀원과 파트너가 회원 · 모임 운영진 · 관리자 역할을 오가며 캠페인을 만들고, 참여하고, 4주를 앞당겨 마무리까지 겪어 본 뒤 "이대로 개발 업체에 넘기자" 또는 "여기는 바꾸자"를 판단할 수 있다.

## 2. 목표 · 하지 않을 것 · 실패로 볼 것

### 목표
1. Figma 「최종 Desktop」 시안의 화면과 흐름을 **실제로 작동하는 반응형 웹**으로 구현한다. **[결정]**
2. 여러 사람이 **같은 데이터를 공유**한다. 한 사람이 쓴 글 · 서명 · 신청 · 기록이 다른 사람 화면에 실제로 보인다. **[결정]**
3. 상단의 **역할 전환 버튼**으로 회원 · 모임 운영진 · 관리자 화면을 모두 써 볼 수 있다. **[결정]**
4. 사람마다 **「내 날짜」를 앞당겨** 캠페인의 모집 → 진행 → 마감을 체험할 수 있다. 날짜를 바꾼 사람의 화면에서만 적용된다. **[결정]**
5. 1.5도 계산기는 **운영 중인 15c 계산기의 28문항 · 계수 · 계산식을 그대로** 쓰고, **감축 행동 고르기도 살린다.** **[결정]**
6. 관리자가 올린 **맞춤 블록(HTML)이 실제로 실행**된다. 실제 플랫폼과 같은 조건이 되도록 **분리된 공간(iframe 샌드박스)** 에서 실행한다. **[결정]**
7. GitHub Pages로 배포한다. **[결정]**

### 하지 않을 것
- 실제 로그인(카카오 · 네이버 · Google · 이메일 인증). 가입 화면 모양은 시안대로 두되, 실제로는 **활동명과 지역만 입력**한다. **[결정]**
- 시안의 예시 캠페인 · 모임 · 게시글을 미리 넣어 두는 것. **빈 상태로 시작**해 체험자가 직접 만든다. **[결정]**
- 실제 푸시 알림 · 이메일 · 문자 발송. 화면 안 알림함으로 대신한다. **[제안]**
- 의견 수합 기능, 통계 분석 도구, 검색 엔진 노출, 다국어.
- 기존 15c.igt.or.kr 사이트와의 데이터 연동.
- 웹뷰 앱, 실제 결제, 실제 지도 API 연동(지도 자리는 그림으로 대신). **[제안]**

### 실패로 볼 것 (작동은 해도 실패)
- 화면에 개발용 표기가 보이는 것. Figma에는 「플랫폼 공통 항목 · 캠페인 설정에 따라 자동 구성」 같은 주석 칩, 「캠페인별 맞춤 영역 · 블록형 샌드박스 · 위치 ②」 같은 점선 라벨, 화면 코드(H-2, D-1p 등)가 있다. **이것들은 실제 사이트에 넣지 않는다.** (사용자가 시안 작업 중 "개발 문구를 화면에 넣지 말라"고 지적한 바 있다.) 맞춤 블록 자리는 사용자 화면에서 점선 없이 자연스럽게 보여야 한다.
- 시안의 운영 규칙과 다르게 작동하는 것(예: 주최 모임 없는 캠페인을 못 만들게 막음, 서명 창에서 서명 후 온보딩을 이탈함).
- 체험자 한 명의 실수(잘못된 HTML 업로드, 이상한 입력)로 다른 사람들의 화면이 깨지는 것.
- 입장 암호 없이 데이터를 읽거나 쓸 수 있는 것.
- 무료 한도를 넘겨 비용이 발생하는 것.

## 4. 전체 구성 **[제안]**

```
[브라우저]  ── GitHub Pages: 정적 SPA (React + TypeScript + Vite, HashRouter)
     │  HTTPS (헤더: 입장 토큰, 사용자 ID)
     ▼
[Cloudflare Worker]  ── REST API, 입장 암호 검증, 권한 검사
     │
     ▼
[Cloudflare D1]  ── SQLite. 모든 데이터와 작은 파일(이미지 · 첨부 · HTML)
```

- 무료 한도: Workers 하루 10만 요청, D1 저장 5GB · 하루 읽기 500만 행. 체험 규모에서 충분하다.
- **파일 저장**: R2는 결제 수단 등록이 필요할 수 있어 쓰지 않는다. 이미지는 브라우저에서 긴 변 1280px · JPEG로 줄여 D1에 저장하고, 첨부 파일과 HTML은 **1개당 1MB 이하**로 제한해 D1에 저장한다. **[제안]**
- **실시간성**: 웹소켓은 쓰지 않는다. 화면을 열 때와 주요 동작 뒤에 다시 불러오고, 알림 수는 **창이 보이는 동안에만 60초마다** 확인한다. 화면 하나에 필요한 데이터는 가능한 한 요청 1번으로 묶는다. **[제안]**
- **요청 한도 관리**: Workers 무료 한도(하루 10만 요청)는 계정 전체 한도이며 기존 Worker(`gmail-multi-mcp`)와 나눠 쓴다. 수십 명 체험 기준으로 하루 수천~1만여 건을 예상한다. Worker는 D1에 하루 요청 수를 세고, 하루 8만 건을 넘으면 쓰기 요청을 막고 화면에 "오늘 체험 한도에 가까워 잠시 멈췄어요"를 띄운다. 무료 플랜은 한도를 넘으면 과금되지 않고 요청이 거절되므로 비용 위험은 없다. **[제안]**
- **저장소**: GitHub `minskapo/climate-citizen-platform-sim`(공개, GitHub Pages는 공개 저장소에서 무료). 로컬 경로 `~/dev/climate-citizen-platform`. 데이터와 암호는 저장소에 넣지 않는다. **[제안]**
- 기술 스택은 [제안]이며 세부 라이브러리 선택은 개발자 재량이다(10장).

## 5. 입장 · 신원 · 역할 · 날짜

### 5.1 입장 암호 **[결정 + 제안]**
- 사이트를 처음 열면 **입장 암호 화면**이 나온다. 공용 암호 하나를 팀원과 파트너에게만 알린다. **[결정]**
- 암호는 Worker의 비밀 값(secret)으로 둔다. Worker는 암호가 맞으면 입장 토큰을 발급하고, **토큰이 없는 모든 API 요청을 거절**한다. 화면만 막는 방식이 아니다. **[제안]**
- 초기 암호: `climate15` **[제안: 값]**. 관리자가 Cloudflare에서 바꿀 수 있다. 바꾸면 기존 토큰은 무효가 된다.
- 토큰은 브라우저(localStorage)에 보관하고 30일 동안 유지한다.

### 5.2 신원 (가입) **[결정]**
- 가입 화면(I, 315:1149)은 시안 모양 그대로 보여 준다. 카카오 · 네이버 · Google 버튼과 이메일 가입 칸도 그대로 두되, **어느 쪽을 눌러도 같은 간단 가입**으로 이어진다: 활동명(필수) · 사는 지역(시·도, 시·군·구) · 동의 항목.
- 활동명은 사이트 전체에서 중복 불가. 가입하면 사용자 ID가 만들어지고 브라우저에 보관된다.
- 「로그인」은 **이미 만든 활동명을 고르는 화면**이다(체험자가 다른 브라우저에서 이어 쓰기 위함). 비밀번호는 없다. 누구나 남의 활동명으로 들어갈 수 있다는 점은 체험용이므로 허용한다. **[제안]**
- 「로그아웃」하면 비회원 상태로 돌아간다.

### 5.3 역할 전환 **[결정 + 제안]**
상단 맨 위(헤더 위)에 얇은 **체험 도구 막대**를 둔다. 플랫폼 화면과 구분되는 색(예: 어두운 회색)으로, 실제 플랫폼에는 없는 체험용 장치임이 분명히 보이게 한다. 막대에는 다음이 있다.

| 항목 | 내용 |
|---|---|
| 지금 역할 | 비회원 · 회원 · 모임 운영진 · 관리자 중 선택 **[결정: 회원·운영진·관리자 / 제안: 비회원 추가]** |
| 활동명 | 지금 들어온 활동명, 바꾸기 |
| 내 날짜 | 5.4 참고 |
| 데이터 초기화 | 관리자 역할일 때만. 6.10 참고 **[제안]** |

- **비회원**: 로그인하지 않은 상태로 보기. 시안의 비로그인 화면(A, G 등)을 체험한다.
- **회원**: 일반 회원. 자기가 가입한 모임 · 신청한 캠페인 기준으로 화면이 바뀐다. 자기가 만든 모임에서는 원래대로 모임장 권한이 있다.
- **모임 운영진**: 전환하면 「운영할 모임」을 고른다(가입한 모임 목록). 체험 편의를 위해 **고른 모임의 운영진 권한을 즉시 받는다**(실제 플랫폼에서는 모임장이 지정해야 함). 모임장 넘기기 · 모임 닫기 같은 모임장 전용 기능은 실제 모임장만 할 수 있다. **[제안]**
- **관리자**: 관리자 화면(/admin, M 계열)으로 들어간다. 관리자 로그인 화면(M-0)은 보여 주되 아무 이메일로나 통과한다. 관리자 행동은 그 사람의 활동명으로 기록된다. **[제안]**
- 역할은 브라우저마다 따로 기억한다.

### 5.4 내 날짜 **[결정 + 제안]**
- 체험 도구 막대의 「내 날짜」에서 날짜를 고르거나 「+1일 / +7일 / 오늘로 돌아가기」를 누른다. **[결정: 기능 / 제안: 버튼 구성]**
- **날짜를 바꾼 사람의 화면에만 적용된다.** 다른 사람에게는 영향이 없다. **[결정]**
- 이 사이트의 모든 "오늘"은 내 날짜다: 캠페인 상태(모집 예정 · 모집 중 · 진행 중 · 마감), D-day, 진행 n일째, 오늘 기록할 미션, 미기록 일수, 시작 전 · 마무리 화면 전환, 모임 당일 QR 출석 가능 시간, 협업 제안 답변 기한 등.
- **저장되는 기록의 날짜**: 미션 기록 · 출석 · 계산기 측정은 **기록한 사람의 내 날짜**로 저장한다(4주 체험이 가능해야 하므로). 글 · 댓글 · 서명 같은 일반 활동도 내 날짜를 표시 날짜로 저장하고, 실제 시각은 따로 저장한다. **[제안]**
- 시간 단위(오프라인 모임의 14:00 시작 등)는 내 날짜의 실제 현재 시각을 쓴다. 「시각 바꾸기」도 함께 둔다(오프라인 당일 체험용). **[제안]**
- 같은 데이터를 보는 두 사람의 날짜가 다르면 서로 다른 상태를 본다. 이는 의도된 동작이다(예: A는 모집 중, B는 진행 중으로 봄). 날짜가 앞선 사람이 쓴 글이 다른 사람에게 "미래 날짜"로 보일 수 있는데, 그대로 둔다. **[제안]**

핵심 규칙(시안 확정 사항):
- 캠페인은 **녹전(관리자)만** 만든다. 사용자 화면에는 「캠페인 협업 제안」만 있다.
- **주최 모임은 연결할 수도, 하지 않을 수도 있다.** 연결하면 신청 시 그 모임에 자동 가입(서명은 설정에 따라 선택 · 자동 · 묻지 않기)되고 모임 게시판에 참가자 전용 캠페인 탭이 생긴다. 연결하지 않으면 주최는 「녹색전환연구소」로 표시되고 참가자 게시판은 캠페인 안에 생긴다.
- 상태는 날짜에서 자동 계산: 모집 예정 → 모집 중 → 진행 중 → 마감. 서명은 진행 중 없음. 오프라인은 모임 날짜가 진행 중.
- 상태별 주 버튼과 인원 표시는 「Note: 상태별 주 버튼」을 따른다.
- **신청 창은 공통 창**이다. 어디서 열든(상세 · 홈 카드 · 온보딩) 같은 창이 지금 화면 위에 뜬다. 상세에서 열었으면 완료 후 완료 화면(H-2 · S-2 · O-2)으로, 그 밖의 곳(온보딩 등)에서 열었으면 **그 자리에 머물고 토스트만** 띄운다. **[제안: 사용자가 마지막에 동의한 정리안을 규칙으로 채택]**

- 결과 저장: 회원은 「나의 탄소 기록」에 측정 위치(홈 · 상단 메뉴 · 캠페인 ID) · 내 날짜와 함께 저장. 비회원은 브라우저에 임시 보관 → 가입 직후 자동 저장(K-2 → I → K-4).
- 캠페인에서 들어온 경우(K-2b): 상단 「← ○○로 돌아가기」, 결과를 캠페인 출발점/마무리 측정으로 함께 저장. 마무리는 캠페인 기간 안의 마지막 측정.
- 계산기는 원래 페이지형 웹 도구지만, 이 사이트에서는 **플랫폼 코드 안에 직접 구현**한다(28문항을 샌드박스 브리지로 옮기는 비용이 크고 체험 목적에 영향 없음). 관리자 「웹 도구」 목록에는 「1.5도 계산기 · 페이지형 · 플랫폼 내장」으로 표시만 한다. **[제안]**

### 6.6 내 활동 · 소개 (섹션 5: E 286:791, F 287:829)
- 내 활동(E): 지금 미션, 참여 중 캠페인(내 상태), 가입한 모임(새 글 수), 지난 캠페인, 나의 탄소 기록(측정 목록 · 고른 감축 행동 · 고른 정책), 기록과 알림 설정(연구 활용 동의 · 미션 알림 · 새 글 알림).

### 6.7 가입 · 온보딩 (섹션 6: K-1 318:1210, K-2 318:1282, K-2b 326:1629, I 315:1149, K-4 319:1293, K-5 319:1360, K-6 319:1451, K-7 319:1516, 메모 319:1558)

### 6.11 맞춤 블록 · 웹 도구 샌드박스 **[결정: 분리 실행 / 제안: 세부]**
- 관리자 「웹 도구」(M-3)에서 HTML을 올린다. 올리기 창(384:1977)은 **HTML 파일 1개(1MB 이하) + 설명 입력란**으로 단순화한다. 설명 입력란이 원래의 `tool.json`(이름 · 규격(블록형/페이지형) · 주소 · 필요한 권한 · 저장 값 · 집계 값 · 출발점 도구로 쓰기 가능 여부)을 대신한다. **[제안]**
- 상태: 게시 대기 → 미리보기(M-3a, 테스트 계정, 실제 기록과 섞이지 않음) → 게시 → 이전 버전으로 되돌리기. 버전 기록. 「시작 템플릿 내려받기」는 브리지 예제가 든 HTML 파일을 내려준다.
- **실행**: `<iframe sandbox="allow-scripts" srcdoc="...">`. 같은 출처 권한을 주지 않아 사이트의 저장소 · 토큰에 접근하지 못한다. 높이는 블록이 알려 주는 값으로 자동 조절.
- **연결 기능(브리지)**: `postMessage`로 아래만 제공한다. 설명란에 적은 권한만 허용.
  - `getUser()` → 활동명, 지역(권한: 사용자 정보)
  - `getCampaign()` → 캠페인 ID · 이름 · 상태 · 내 날짜 · n일째(권한 없이)
  - `getParticipation()` → 참가 여부 · 출발점(권한: 캠페인 참가 여부)
  - `saveRecord(values)` / `listMyRecords()` → 설명란의 저장 값만(권한: 기록 저장)
  - `getAggregate(key)` → 설명란의 집계 값(합계 · 평균 · 참여자 수)
  - `resize(height)`, `toast(text)`
- 페이지형 웹 도구는 상단바 아래 전체 화면 iframe으로 연다(주소 `/#/tools/{slug}`).
- 「웹 도구로 기록」을 고른 캠페인은 웹 도구가 `saveRecord`로 넘긴 값을 그 캠페인의 미션 기록(숫자 등)으로 저장한다.

## 7. 데이터 · 권한 원칙 (사업계획서 「데이터 활용」)
- 개별 기록(계산기 기록 · 캠페인 기록)은 본인과 그 캠페인 주최 모임 운영진, 관리자만 본다.
- 연구 활용 동의자만 익명 집계 내려받기에 포함한다.
- 서명의 활동명 · 지역 · 실명 · 의견은 운영자와 전달처(전달용 명단)만 본다. 공개 화면은 서명 수만.
- 오프라인 모임의 정확한 주소는 신청자에게만.
- 연락처(전화번호 · 이메일)는 받지 않는다.
- 권한 검사는 **Worker에서** 한다(화면에서 숨기는 것만으로는 안 된다). 단, 역할 전환으로 누구나 관리자가 될 수 있으므로, 권한 검사의 목적은 보안이 아니라 **실제 플랫폼의 권한 규칙을 체험에서 재현**하는 것이다.

## 8. 데이터 모델 (요약) **[제안 — 세부는 개발자 재량]**
`users`(활동명, 지역, 동의, 설정) · `groups` · `group_members`(역할: 모임장/운영진/멤버/대기/차단) · `posts`(모임 또는 캠페인 게시판, 분류, 고정, 숨김) · `comments` · `reactions` · `reports` · `campaigns`(유형, 설정 JSON, 일정, 공개 상태, 주최 모임 nullable) · `campaign_versions`(임시 저장) · `missions` · `mission_bundles` · `checklist_items` · `participations`(신청 · 서명 · 대기 · 취소 · 중단, 동반 인원, 동의) · `records`(미션 기록, 내 날짜) · `attendance` · `measurements`(계산기 응답 · 결과 · 고른 행동 · 정책, 위치) · `tools`/`tool_versions`(HTML) · `tool_records` · `files` · `notifications` · `collab_proposals` · `deliveries`(서명 전달 결과 · 답변) · `audit_log`.

## 9. 반응형 **[결정: 반응형 / 제안: 방식]**
- 시안은 데스크탑(1440)만 있다. 모바일 시안은 없다.
- 기준 폭: 1200 이상 데스크탑(시안 그대로), 768~1199 태블릿(옆 패널이 본문 아래로), 767 이하 모바일(한 줄 배치, 좌우 여백 16px).
- 모바일 헤더: 로고 · 「1.5도 계산기」 버튼 · 메뉴 버튼(펼치면 홈 · 캠페인 · 모임 · 내 활동 · 소개 · 로그인/알림). 체험 도구 막대는 모바일에서 접힌 상태(눌러서 펼침).
- 모바일에서 신청 · 서명 창은 아래에서 올라오는 시트. 캠페인 상세의 주 버튼(신청하기 · 서명하기 · 오늘 기록하기)은 하단에 고정.
- 관리자 화면은 태블릿 이상을 기준으로 하되, 모바일에서도 깨지지 않게(표는 가로 스크롤).
- 오프라인 모임 당일 QR 출석은 모바일 사용이 기본이다.

- 이미지 축소 방식, 파일 형식 제한.

## 11. 남은 확인 사항 (작성자가 정한 기본값)
- 협업 제안 「1일」 기준: 달력 24시간으로 구현(사용자가 영업일을 원하면 변경).
- 사업계획서와 시안의 차이: 사업계획서의 (캠페인 운영) 문단은 아직 "모든 캠페인은 주최 모임 하나에 속함"이고, 도구 게시판 관련 문단도 남아 있다. **이 사이트는 시안(최신 결정)을 따른다.** 사업계획서 수정은 별도로 사용자 승인을 받아 진행한다.
